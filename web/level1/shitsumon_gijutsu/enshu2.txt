【What（何を）】
ユーザー編集時、メール重複エラーのレスポンスが統一されていない問題を確認。

【Why（なぜ）】
仕様の揺れがあると、フロント側のハンドリングが不安定になるため、早急に方針を固めたい。

【Who（誰が）】
自分（mugiw）がAPI挙動を調査中。

【When（いつまでに）】
本日中にエラーコード運用方針（200/409 のどちらに統一するか）を決めたい。

【Where（どこで）】
Chrome（v126）＋ API v2.3（/users PUT）で確認。

【How（どうやって確認したか）】
ユーザー編集で重複メールを入力して送信したところ、同じ操作でも 200 が返る時と 409 が返る時があることを再現。

【Fact（事実）】
・同一メールでPUT /usersを実行した際、200 と 409 の両方が発生  
・再現条件：同一メールでの更新  
・環境：Chrome / API v2.3

【Guess（推測）】
・Validation と Domain 層で処理が分かれている可能性  
・一部のパスで重複チェックがスキップされている可能性

【理解度レベル】
レベル3：手段候補はあるが正しいか確信が持てない  
（A：常に409で統一、B：更新内容に応じて200/409分岐。ただし仕様が不明。）

【欲しい回答の型】
設計方針の判断（A / B のどちらに統一するべきか）。  
可能であれば、既存APIでの類似ケースの基準も確認したい。
